## Correction-round exhaustive boundary analysis (recorded before edits)

### Defect-class locations and lifecycle paths

- **A — retired-evidence ordering/freshness:** Real state can enter or consume
  retirement history at `GitWorktreeManager.retire` (`_retired` and
  `_retired_branches`), `register_retired` (restart restoration into both
  indexes), `prepare` / `_authorize_retired_branch_reuse` (later-attempt
  authorization), and repeated `retire` (path-keyed cached evidence). `register`
  and `resume` create/consume active ownership that must fence retirement
  restoration, while external loss between restart observations can remove the
  Git path/registry evidence without proving the latest process or effect safe.
  The fake has the same entry/consumption paths in `retire`,
  `register_retired`, `prepare`, `register`, `resume`, and its `_retired`,
  `_retired_branches`, `_active`, `_workspaces`, and `_branches` indexes.
  Every branch-history write must therefore reject an older/different durable
  record when a newer record is already authoritative; an idempotent repeat of
  the identical record is the only non-advancing restoration. Retirement of a
  currently active later lease is the only operation allowed to advance the
  branch's retirement record.
- **B — preserved-branch recreation/disappearance:** Real `prepare` has both an
  existing-branch reuse path and a missing-branch `worktree add -b` path. The
  latter currently bypasses durable `_retired_branches` evidence and can
  recreate a disappeared preserved branch. `_authorize_retired_branch_reuse`
  and `_branch_head` validate only the existing-branch path. The fake's
  `prepare` similarly chooses new-branch creation when `_branches` is missing,
  even if `_retired_branches` proves the branch is supposed to be preserved.
  Both implementations must fence missing preserved branches before any
  workspace, active-owner, branch, or action-log mutation.
- **C — retired lease terminality:** Real `prepare` can reconstruct the exact
  retired lease/path because `_retired` is not consulted; repeated `retire`
  returns cached evidence before inspecting Git/path state, so an externally
  reappearing path can survive a claimed idempotent retirement. The relevant
  real paths are `prepare`, `register`, `register_retired`, `inspect`, `resume`,
  `retire`, `_authorize_retired_branch_reuse`, `_inspect_lease`, `_retired`, and
  `_leases`. The fake has the same exposure through `prepare`, `seed_existing`
  or other external-state helpers, `register`, `register_retired`, `inspect`,
  `resume`, `retire`, `_retired`, `_active`, and `_workspaces`. Once a lease is
  retired, no public lifecycle entry point may reactivate it; duplicate retire
  is idempotent only while the retired path remains absent, and reappearance
  fails closed without deleting or adopting it.
- **D — fake branch-conflict scope:** Real Git attachment checks are scoped to
  one repository because `_list_worktrees(repository)` cannot observe another
  repository, and active ownership is keyed by repository plus branch. Fake
  `prepare` and `register_retired` scan every `_workspaces` value by branch name
  alone. `_workspaces`, `_active`, `_retired`, and `_dirty` are absolute-path
  indexes; `_branches` and `_retired_branches` are repository/branch indexes.
  Every fake branch attachment/conflict query must use the lease repository
  plus branch (and retain task/issue/attempt identity in the lease), so equal
  branch names in unrelated repositories/tasks do not conflict while equal
  branches inside one repository still do.

### Boundary questions applied to retired leases, preserved branches, and fake state

1. **Checks and false-pass cases:** A path-absence check can pass after an
   active later worktree was externally removed; branch ancestry can pass for
   stale evidence when attempts share a head; branch absence can pass after a
   preserved ref was deleted; a cached-retirement check can pass while the path
   has reappeared; and a branch-only fake scan can report attachment from the
   wrong repository. Negative regressions will cover stale a01 evidence after
   a02 retirement/history, missing preserved refs before new-branch creation,
   exact retired-lease reprepare plus reappearing paths/repeated retirement,
   and equal branch names across repositories for both prepare and
   `register_retired`.
2. **Accepted records, fields, and variants:** `WorktreeRequest` accepts and
   validates `repository`, `worktree_root`, `task_id`, positive non-bool
   `issue_number`, `attempt_id`, and full lowercase `base_sha`; derived
   `branch`/`worktree` are not caller variants. `WorktreeLease` accepts those
   fields plus exact derived `worktree` and `branch`; `from_dict` rejects
   missing/extra fields and wrong scalar variants. `RetiredWorktreeEvidence`
   accepts exactly `lease` and full lowercase `head_sha`; `from_dict` rejects
   missing/extra/wrong variants. `PriorProcessState` has RUNNING, STOPPED, and
   UNKNOWN; only STOPPED is accepted for recovery/retirement. Git worktree
   records consume `worktree`, `HEAD`, optional `branch`, and intentionally
   ignore other porcelain fields. Fake seed helpers accept explicit head,
   ancestor list, and directed relation variants solely as test-controlled
   external state.
3. **Public-entry bypasses:** `prepare`, `register`, `register_retired`,
   `inspect`, `resume`, and `retire` must all respect retired terminal state;
   neither branch disappearance nor a different entry point may bypass it.
   Fake-only `seed_existing`, `seed_preserved_branch`, `remove_externally`, and
   `set_dirty` model external/test state and must not silently grant controller
   ownership. Regression setup may use them, but lifecycle authorization must
   still flow through the public manager operations.
4. **Identifier/key scope:** Lease worktree paths are globally absolute and
   unique per repository root/issue/attempt; active path keys are therefore
   path-scoped. Issue branch identity and retirement history are unique within
   `(repository, branch)`, not globally by branch text. Lease identity includes
   repository, root, path, task, issue, attempt, branch, and base. Retired
   terminal identity is the exact lease at its exact path; fake workspace
   attachment queries must use `(repository, branch)`.
5. **Mutation ordering and failure atomicity:** Validate process state,
   filesystem/record identity, ownership, retirement freshness/terminality,
   path absence, branch presence, and ancestry before Git creation/removal or
   fake index/action mutation. A failed prepare/register/register-retired must
   leave active, retired, branch, workspace, dirty, and action state unchanged.
   After a successful external Git create/remove, ownership is retained until
   postconditions reconcile; unexpected reappearance during idempotent retire
   is reported without deletion.
6. **Real/fake parity:** The fake must enforce real repository-scoped branch
   attachment, identical-vs-conflicting retired restoration, preserved-branch
   loss, exact-lease terminality, process gates, dirty gates, ancestry, and
   repeated-retire behavior. The A/B/C/D regressions will exercise corresponding
   real and fake lifecycle cases wherever external Git behavior exists, and all
   F001-F005 regressions remain required.
