## Decisions and blockers

- Mutations must be effect-journaled before invocation; uncertain timeouts must
  reconcile through remote reads before retry.
- This work is path-disjoint from active MB-018/a01.
- A remotely observed completed effect is never re-created if its marker later
  disappears; that inconsistent state is surfaced for controller recovery.
- Update operations carry the marker in the issue body so label/close effects
  are remotely reconcilable without introducing an unjournaled side mutation.
- A marker is reserved per repository and contains the effect ID plus canonical
  semantic digest. A conflicting local journal request or remote marker is a
  typed conflict and cannot be adopted.
- A transport, protocol, or response-shape failure after `CALL_STARTED` is
  non-definitive: the journal moves to `UNCERTAIN` and recovery must read remote
  state before any retry.
- Create and comment observation requires both one exact full-body marker and
  the exact requested title/body or comment body/issue correlation.
- Preparing an update may read remote state, but `CALL_STARTED` and its final
  task/attempt generation assertion occur only immediately before the mutation.
- `RECONCILED` is a retryable pre-call checkpoint: a definite preparation
  failure performs no mutation and retry does not append an invalid duplicate
  transition; call-started and uncertain paths retain their strict transitions.
- Blockers: none.
